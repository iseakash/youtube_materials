The Problem
Containers are ephemeral by design.

When a container is removed, everything inside it — including database records — is destroyed.

# Data exists only inside the container's writable layer
docker compose up -d
# ... add data through the app ...
docker compose down
# ❌ Data is gone forever
🤔

Question: How do we keep data safe when containers come and go?

Persistent storage managed by Docker, stored on the host filesystem.

docker-compose.yml (Annotated)
Volumes are commented out by default — uncomment to enable persistence.
services:
  db:
    image: mysql:8
    environment:
      MYSQL_ROOT_PASSWORD: rootpassword
      MYSQL_DATABASE: sales_db
    # --- STEP 2: Uncomment for persistence ---
    # volumes:
    #   - sales_data:/var/lib/mysql

  app:
    build: ./app
    ports:
      - "5000:5000"
    depends_on:
      - db

# --- STEP 2: Uncomment this too ---
volumes:
  sales_data:
Important: Named volumes must be declared at the top-level volumes: key in Compose.

DEMO: Without Volumes ❌
Data stored in the container's ephemeral layer — lost on deletion.
#ActionCommand
1Start the stackdocker compose up -d
2Open http://localhost:5000—
3Add 2–3 sales via the UI—
4Tear everything downdocker compose down
5Restart the stackdocker compose up -d
6Data is gone — empty tableDATA LOST
Why? docker compose down removes containers. Without a volume mount, MySQL's /var/lib/mysql is inside the container and gets destroyed with it.
06 / 10
DEMO: With Volumes ✅
Data stored in a named volume — survives container recreation.
First: Edit docker-compose.yml — uncomment the volume lines.
#ActionCommand
1Start the stackdocker compose up -d
2Open http://localhost:5000—
3Add 2–3 sales via the UI—
4Tear everything downdocker compose down
5Restart the stackdocker compose up -d
6Data is restored — full tableDATA RECOVERED
Why? The volume sales_data is mounted at /var/lib/mysql. MySQL writes to the host filesystem. Deleting the container leaves the volume untouched.

Volume Management Commands
Inspect, list, and remove Docker volumes.

List & Inspect

# List all volumes
docker volume ls

# Inspect a specific volume
docker volume inspect \
  docker-volume-demo_sales_data

Remove & Cleanup

# Remove a specific volume
docker volume rm \
  docker-volume-demo_sales_data

# Remove all unused volumes
docker volume prune

Key Takeaways
What to remember about Docker volumes.
📖 Core Concepts
  • Containers are ephemeral — data inside dies with them
  • Volumes are persistent — data survives container deletion
  • Named volumes — Docker-managed, declared in docker-compose.yml
  • Mount at data dir — MySQL → /var/lib/mysql
