Docker Compose Configuration

4 services, 1 volume, 1 network — 1 file

version: "3.8"
services:
  db:
    image: postgres:16-alpine
    volumes: [postgres_data:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USER}"]
  backend:
    build: ./backend
    depends_on:
      db: { condition: service_healthy }
  frontend:
    build: ./frontend
    ports: ["3000:3000"]
  nginx:
    build: ./nginx
    ports: ["80:80"]
volumes: { postgres_data: }
networks: { ems-network: { driver: bridge } }

Health Check

"Call ahead to make sure the kitchen is open before placing the order." Backend waits for DB.

depends_on

Start order: DB → Backend → Frontend → Nginx. Each waits for the previous.

ems-network

All containers on one bridge network — they talk by service name, not IP.

How to Run

# Build & start all services
docker-compose up --build

# Open in browser
→ http://localhost

# Stop everything
docker-compose down

# Stop + delete DB data
docker-compose down -v

    How It All Connects

    Page Load

    1. 1. Browser → Nginx (port 80)
    2. 2. Nginx → Frontend (port 3000)
    3. 3. React page loads → JS runs
    4. 4. JS → localhost:5000/api/employees
    5. 5. Backend → PostgreSQL → returns data
    6. 6. JSON back to browser → table renders

    Add Employee

    1. 1. Fill form → click "Add"
    2. 2. POST with JSON body
    3. 3. Backend validates
    4. 4. INSERT ... RETURNING *
    5. 5. Returns 201 + new record
    6. 6. Toast + re-fetch → table updates

    End-to-end: Browser → Nginx → Frontend → API → Backend → DB → Response full circle
